# Merge PR（合併拉取請求並收尾）

把使用者確認過內容的拉取請求（PR）合併進 `main`，刪除用完的工作分支，並把本機更新到最新狀態。

這個 skill 只負責「關」：建立 PR 是另一個 skill（`open-pr`）的事。合併的前提是使用者已經檢視過 PR 的內容；如果他沒有明確表示確認過，先問一句再繼續。

## 執行步驟

1. 用 `gh pr view` 確認目前分支對應的 PR 存在、狀態還是開啟（OPEN）；找不到 PR 或已經關閉，停下來回報，不要自己補救。
2. 把即將執行的指令列給使用者確認，使用者確認之前不要執行：

   ```
   gh pr merge --merge --delete-branch
   ```

   - `--merge`：用「建立合併提交」的方式合併，維持課程的做法。
   - `--delete-branch`：合併後把 GitHub 上與本機的這條工作分支一起刪掉（一個分支＝一個任務，用完即刪）；gh 會在刪除本機分支前自動切回 `main`。
3. 使用者確認後執行，接著用 `git pull` 把本機的 `main` 更新成 GitHub 上的最新內容。
4. 回報：目前所在的分支、剩下的本機分支，以及最近幾筆提交紀錄，讓使用者核對合併結果。

## 不要做

以下的事不在這個 skill 的範圍內。合併完成、回報完狀態，這次任務就結束了，下一步等使用者開口：

- 不要用 `--squash` 或 `--rebase` 合併，也不要繞過 PR 直接把分支併進 `main`。
- 不要發新的 PR——那是 `open-pr` 的事。
- 不要主動修改任何檔案，也不要順手提交或開分支。
- 只執行這些指令：`git status`、`git branch`、`git log`、`git pull`、`gh pr view`、`gh pr merge`。清單以外的 git／gh 指令一律不執行。
