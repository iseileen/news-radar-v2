# Open PR（發拉取請求）

依這門課的慣例，把使用者目前的工作分支推上 GitHub，並用 `gh pr create` 建立拉取請求（PR）。

這個 skill 只負責「開」：PR 建立後就停。合併收尾是另一個 skill（`merge-pr`）的事，等使用者檢視過 PR 內容、另外開口才會進行。

## 內容規範

1. 標題（Title）：一句中文講清楚這個 PR 要做的事（例如「將 W1 進度標記為完成」），不加類別前綴。
2. 內文（Body）：固定用三個小標題撐起結構，每段用條列式，寫給審核的人看：

   ```markdown
   ## 這次改了什麼
   - （列出實際的改動）

   ## 為什麼要改
   - （說明改動的原因或目的）

   ## 怎麼驗證
   - （說明怎麼確認這次改動沒問題）
   ```

## 執行步驟

1. 先看清楚這條分支相對於 `main` 改了什麼：`git log main..HEAD --oneline` 與 `git diff main`。
2. 依「實際的改動」寫好標題與三段式內文，不要憑空猜測。
3. 把標題、內文，以及接下來要執行的指令，完整列給使用者確認；使用者確認之前，不要執行任何會改變狀態的指令。
4. 使用者確認後，依序執行：
   - 推送分支：`git push -u origin 分支名稱`
   - 建立 PR：`gh pr create --title "標題" --body "內文"`（不指定合併目標，gh 會自動用預設分支 `main`）
5. 回報 PR 的網址與編號，並提醒使用者先自己檢視 PR 的內容；等他確認過再開口進行合併。

## 不要做

以下的事不在這個 skill 的範圍內。PR 建立並回報網址，這次任務就結束了，下一步等使用者開口：

- 不要合併（merge）PR、不要刪除分支、不要動 `main`——合併是 `merge-pr` 的事，而且要等使用者確認過內容。
- 不要主動修改任何檔案，也不要順手補提交；發現分支上還有未提交的變更，先停下來問使用者。
- 只執行這些指令：`git status`、`git branch`、`git log`、`git diff`、`git push`、`gh pr create`、`gh pr view`。清單以外的 git／gh 指令一律不執行。

## 範例

以「將 W1 進度標記為完成」這個任務為例，建立的 PR 會像這樣：

- 標題：`將 W1 進度標記為完成`
- 內文：

  ```markdown
  ## 這次改了什麼
  - 把 data.js 中 W1 的 completed 從 false 改成 true

  ## 為什麼要改
  - W1 的實作練習已經完成，讓儀表板正確顯示為已完成

  ## 怎麼驗證
  - 合併後重新整理 GitHub Pages 的網址，確認 W1 顯示為「已完成」
  ```
