# 審查 PR

用審查者（reviewer）的角度檢視目前工作分支相對於 main 分支的改動，給出條列的審查意見。

## 審查重點

依序檢查以下四件事：

1. **一個分支一個任務**：分支名稱宣告的任務，與實際改動是否一致；有沒有夾帶無關的改動。
2. **提交訊息**：是否符合「類別: 中文描述」格式（feat/fix/docs/chore），描述是否講清楚做了什麼。
3. **改動內容**：有沒有明顯的錯誤——語法問題、改壞的引號或括號、看起來像手滑的多餘變動。
4. **不該進版控的東西**：改動裡有沒有夾帶權杖、金鑰、密碼之類的機密字串；有的話標為最嚴重問題，提醒立刻移除並重發權杖。

## 執行步驟

1. 執行 `git log main..HEAD --oneline` 與 `git diff main...HEAD`，看清楚這條分支做了什麼。
2. 依上面四個重點逐一檢視。
3. 條列輸出意見，每一條標明：位置（檔案與大概行數）、問題、建議的修法。沒有問題的項目也簡短說一句「通過」。
4. 結尾給一個總結：「建議直接開 PR」或「建議先修正第 N 點再開 PR」。

## 不要做

- 不修改任何檔案——審查者提意見，動手的是作者。
- 不執行 `git add`、`git commit`、`git push` 或任何 `gh` 寫入操作。
- 只准執行：`git status`、`git log`、`git diff`、`git branch`、`gh pr view`、`gh pr diff`；清單以外一律不執行。
- 不因為改動很小就跳過檢查步驟。
